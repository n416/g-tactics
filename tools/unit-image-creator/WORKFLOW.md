# Unit Image Creator ワークフロー

本ツール群は、大量の2Dドット絵等のアセットを高解像度の画像（AIによる生成・アップスケール等）へ一括置換し、検収・修正を自動化・半自動化するためのパイプラインです。

## ディレクトリ構成
- `produce.py` : メインの画像生成エンジン。マニフェストを読み込み、APIを叩いて画像を生成、背景透過、見切れ検査までを全自動で行います。
- `generate_full_review.py` : 全機体の生成結果をブラウザで一覧表示するためのHTML (`check-review.html`) を生成します。
- `generate_recheck_review.py` : 見切れエラー等で弾かれた（未完了の）機体のみをリストアップするHTML (`recheck-review.html`) を生成します。
- `generate_manual_selector.py` : エラーでどうしても生成できない機体に対し、手動で参考画像を探すための支援HTMLを作成します。
- `apply_manual_refs.py` : 手動で見つけてきた設定画等のURLを読み込み、AIが認識しやすいように加工（余白の自動追加など）して投入します。

---

## 基本的な運用フロー

### 1. 初回の一括生成
対象となる機体リストを `manifest.csv` に定義し、生成エンジンを起動します。
```bash
python produce.py 999
```
※ 引数の数値は同時実行・処理の上限数です。APIのクォータ（制限）に達すると自動で待機・リトライを行います。

### 2. 全体レビューとエラーの確認
生成が完了したら、以下のスクリプトで一覧HTMLを生成してブラウザで確認します。
```bash
python generate_full_review.py
```
ここで出力された `check-review.html` を開き、意図しない形状になっているものや、見切れてしまっているものを確認します。

### 3. リテイク（再生成）の実施
AIが誤った解釈をした機体については、`produce.py` 内に個別のプロンプトを追加して再出力をかけます。
未完了の機体だけを抽出して確認するには以下を実行します。
```bash
python generate_recheck_review.py
```
生成された `recheck-review.html` には自動更新（オートリフレッシュ）機能がついているため、ブラウザを開きっぱなしにしながら裏で `produce.py` を回すことで、リアルタイムに生成結果をプレビューできます。

## 【重要】プロンプトとリテイクのコツ

AIによる画像生成において、元のドット絵だけでは情報量が足りず、意図しないパーツ（存在しない足など）が生えてしまうことがあります。その際のリカバリーテクニックを記載します。

### 1. プロンプトは「超シンプルに・否定形で強く」
細かい形状をごちゃごちゃと指定するよりも、**「絶対に〇〇を描画しないでください」** と端的に禁止事項だけを伝える方が、AIが混乱せず元絵のシルエットに忠実になります。
* ❌ 悪い例: 「下半身は細長くて四角い筒状のプロペラントタンクになっており、足はありません」
* ⭕ 良い例: 「【超重要】絶対に脚（足）を生やさないでください。」

### 2. 見切れエラー（edge-clip）対策には「パディング（余白）」
AIが武器や肩幅を大きく描きすぎてキャンバス外にはみ出してしまう（見切れる）場合、プロンプトで「小さく描いて」と指示するよりも、**参考画像（元絵）自体の周囲に巨大な透明の余白（パディング）を物理的に付け足す**アプローチが最も確実です。
（本ツールの `apply_manual_refs.py` にはこの余白追加ロジックが標準搭載されています）

### 3. Image-to-Image（I2I）の活用
何度やっても形状が破綻する場合は、以下の手順で強制突破します。
1. `generate_manual_selector.py` を使い、ウェブ上からその機体の「公式設定画」や「プラモデルの鮮明な写真」等の高解像度画像を探す。
2. 見つけた画像のURLを `manual_refs_urls.json` に記載する。
3. `python apply_manual_refs.py` を実行し、その高画質画像を「ベース画像（元絵）」としてAIに読み込ませる。

これにより、AIの「不確かな推測」を排除し、設定画のディテールを保ったままゲーム内の画風（シェーディング等）に変換させることが可能です。
