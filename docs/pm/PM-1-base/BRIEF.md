## 背景

同ディレクトリの `reference-mock-original.html` が出発点のデザイン案（基地＋博物館の複合モック。
img の base64 は `...[TRUNCATED]` で省略されている。壊れた img はプレースホルダー div に置き換えてよい）。
このデザインは**絶対ではなく**、現行アプリのデザインに合わせて作り直すのが本依頼の目的。

今回の PM-1 のスコープは**基地ページの骨格と施設システムのみ**。博物館ホールの中身（展示グリッド・殿堂）は
別スレッド PM-3 の管轄なので、モックでは博物館を「施設カードの1つ＋ページ内のプレースホルダー区画」までに留めること。

## モックが現行アプリに合わせるべき点（必ず実物を読むこと）

- `frontend/src/index.css` — デザイントークン（CSS変数）・共通クラス。モックはこのトークンに準拠する
- `frontend/src/components/AppLayout.tsx` と `AppLayout.css` — 実際のアプリバー/ナビ構造。モックのヘッダーは実物の見た目を再現する
- `frontend/src/components/nav.ts` — 実際のナビ項目。参照モックの「マイページ/格納庫/基地/戦闘/大会/派閥」は実物と違う可能性が高い
- 既存ページの雰囲気の例として `frontend/src/pages/MyPage.tsx` か `Hangar.tsx` を1つ読むとよい

## モックに含める要素

1. 基地ヘッダー: 基地名、地形属性チップ、資金収入チップ、防衛ログサマリ（「リプレイを見る」リンクはダミー）
2. 施設カード5種（発電所 / 修理ドック / 砲台 / 博物館 / 工場）: Lv・効果・次Lvコスト・未建設状態・建設ボタン
3. 施設のLvアップ/建設の確認モーダル（1つでよい。`frontend/src/components/Modal.css` の見た目に合わせる）
4. 博物館区画のプレースホルダー（「PM-3で設計」と注記）
5. 右下に DESIGN MOCK 注記（参照モックと同様）

## ECONOMY.md に含める内容

現行経済の実態を必ず調査して根拠にすること:
- 機体価格帯: `backend/migrations/0001_baseline.sql` の units の price（400〜850G 程度が多い）
- 戦闘報酬: `backend/src/utils/battleRewards.ts` の rewardMoney の算出
- 初期資金や leveling: `backend/src/routes/auth.ts` の登録処理

そのうえで:
1. 各施設の Lv1〜5 の効果値と建設/強化コストの表（発電所の時間収入、修理ドックの回復倍率、砲台の迎撃回数/威力、博物館の展示枠数、工場の割引率）
2. 時間収入の受け取り方式の提案（訪問時精算+上限キャップ方式を推奨ベースに、放置ゲー化しない理由付け）
3. 「発電所収入が戦闘報酬を食わない」ことを示す簡単な試算（1日あたりの収入比較）
4. 論点リスト（地形属性はどこから来るか、基地は1人1つか、等）
