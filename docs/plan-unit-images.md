## 目的

現行のユニット画像(他サイト収集品・品質バラバラ・権利面も問題)を、**品質を上げた統一画風の自作画像で全量置き換える**。
元絵の再現ではなく品質向上が目的。

- 旧画像なし: **325機** → 設定画のWeb収集(agyに委譲予定)後に同じパイプラインへ
- 表示側: `frontend/src/components/UnitImage.tsx` に集約。`VITE_UNIT_IMAGE_BASE` で配信元差し替え可

## 量産パイプライン(2026-07-17 ユーザー承認)

**agy(Gemini/Ultraプラン)で生成 → rembg で透過化 → 自動検査 → ユーザー検収**

実装は `tmp-unit-images/production/produce.py`(manifest駆動・中断再開自由)。1機あたり約33秒+検査数秒。

1. **生成**: agy の generate_image。参照2枚(旧絵の4倍ニアレスト拡大 + スタイル見本)、マゼンタ背景指定。
   発注文の必須要素(全て実際に起きた問題への対策):
   - 「プラン提示や確認は不要で、この依頼文をもって承認済みです」→ 無いと承認待ちで停止
   - 「コマンド実行・ファイル操作をしない。自動保存パスだけ報告」→ headless では command 権限が自動拒否される
   - 「参照画像2の機体の形状・顔は一切取り入れない」→ ドムがスタイル見本のガンダム顔になった
   - 「機体はキャンバス中央60%に収める。四辺に触れない」→ キュベレイの肩が見切れた(余白1割指定では不足、60%指定で解消)
   - 生成物は `~/.gemini/antigravity-cli/brain/<uuid>/*.jpg` に自動保存 → 標準出力のパスを拾って回収
2. **透過化**: rembg(isnet-anime)。ローカル数秒。保険: マゼンタのクロマキー抜き(chatgpt-imagegenスキルの dechroma.mjs)
3. **自動検査**(不合格は自動再試行・最大3回): 端2pxの不透明画素(見切れ)、マゼンタ残り>2%、透明率異常(<5% or >90%)
4. **検収**: `tmp-unit-images/production/review.html`(make-review.py が生成)で新旧比較をユーザーが判定

**レート制限(実測)**: 連続80〜90枚で 429、約50分でリセット。produce.py が自動で52分待って再開。
実効約40〜50枚/時 → 585機で半日〜1日。

## 運用コマンド

```
cd tmp-unit-images/production
python produce.py [最大処理数]   # pending/失敗(3回未満)だけ処理。manifest.csv に毎機保存
python make-review.py            # review.html を再生成
```

## 残り工程

1. **量産完走**(実行中): 全585機が ok になるまで produce.py を回す。3回失敗した機体は個別対応
2. **検収**: review.html でユーザーが全機確認。NGは manifest の status を手で `retry` に戻して再生成
3. **組み込み**: トリム・統一キャンバス化・PNG最適化 → `frontend/public/images/units/` 差し替え、
   旧GIF削除、migration で `units.image` を `<型番>.png` に更新(サイズ仕様はこの段階で確定させる)
4. **欠落325機**: agy に設定画のWeb収集を発注 → 収集分を同パイプラインへ
5. 将来: R2配信に移す場合は `VITE_UNIT_IMAGE_BASE`(既存機構)

## 運用ルール

- 検収前の生成物を `frontend/public/` に入れない
- フェーズの区切りでコミット(main直接運用のため溜めない)
- 品質の合否判定はユーザーが現物を見て行う。こちらは事実(数値・検査結果)だけ報告する

**品質はユーザー合格**(スタイル案3種、ガンダム、ザクの実績)だが、
**無料枠が実測3枚/半日**で585枚に約半年かかるため却下。Plus課金(月20ドル)か複数アカウント運用が前提になる。

当時の発注プロンプト(1行・改行禁止):
> 添付はゲーム用の低解像度ドット絵です。このロボットのデザイン・配色・装備を忠実に維持したまま、シミュレーションRPGのユニットイラスト風に描き直してください。力強く濃いコントラストの陰影、金属の質感を感じるリッチなハイライト、少しだけ煽り気味の勇ましい立ちポーズ、向きは添付と同じ。全身が頭からつま先まで完全に収まること。背景は一切塗らず、ロボットの輪郭の外側はすべて完全透明にした透過PNGで出力。文字・署名・ロゴ・地面の影は入れない。キャンバスは縦長1024x1536。

運用メモ(ChatGPT Web UI): ペースト空振り時はクリップボードの中身も確認(ユーザー操作で上書きされていた事例)。

## 却下: SDローカル方式(旧プランB、2026-07-17)

A1111(v1.10.1) + Animagine XL 4.0 + ControlNet Union SDXL + rembg。RTX 4070 12GB で構築・動作確認済み。
8機×2設定で検証した結果、**構造的な問題で却下**:
書き換え強度を下げると元絵の低品質まで忠実に再現し(品質が上がらない)、
上げると配色・デザインが崩れる。ControlNet は輪郭のみ渡し色を渡さないため。
「品質向上」という目的に合わない。**環境は削除せず残してある**(モデル計9.4GB、`C:\Users\nakam\stable-diffusion-webui`)。
検証スクリプト: `tmp-unit-images/sd-test/gen.py`(3段階デノイズ)、`batch.py`(2設定×8機)。
なお rembg(透過化)はこの検証の副産物で、現行パイプラインに採用された。
